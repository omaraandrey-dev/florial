# Журнал изменений Florial

## 2026-10-22 — SEO LocalBusiness для точки в Несебре

- Добавлена структурированная сущность Schema.org `GardenStore` для подтверждённой точки Florial в Несебре на главной странице и странице контактов.
- Указаны только данные, предоставленные владельцем: телефон, улица, почтовый индекс, город и график понедельник–пятница 09:00–17:00.
- Сущность связана с существующей `Organization` через стабильные `@id`; существующая разметка Organization сохранена.
- Не добавлены координаты, фотографии, рейтинг, юридические сведения или адрес точки в Равде, поскольку эти данные отдельно не подтверждены.
- Проверка live HTML и Google Rich Results Test после deployment остаётся обязательной.


## 2026-10-22 — Дополнительные исправления edge SEO

- Добавлено исключение для файлов подтверждения Google формата `/googleXXXX.html`: middleware пропускает их к Cloudflare Pages static assets вместо обработки как неизвестного маршрута. Фактический файл подтверждения в репозитории не добавлялся; доступность можно подтвердить только после размещения выданного Google файла или настройки DNS TXT.
- Добавлено явное кэширование ответов Sanity через Cloudflare Cache API: найденные документы кэшируются на 300 секунд, отрицательные результаты — на 60 секунд. Ошибка кэша не блокирует прямой запрос к Sanity.
- При ошибке запроса к Sanity middleware теперь возвращает HTTP 503 с `Retry-After`, а не маскирует сбой как обычный ответ SPA. Это отделяет временную недоступность API от настоящего 404.
- Product JSON-LD включает `brand`, если имя бренда доступно из ссылки Sanity. Если у товара нет цены, `offers` не создаётся с пустой ценой. `priceValidUntil`, стоимость доставки и политика возврата не добавляются без подтверждённых данных.
- Canonical для RU/EN URL сохраняет текущую языковую версию даже при `noindex` и на edge middleware, и в клиентском `src/lib/seo.ts`; варианты с неполным переводом или явным `seo.noIndex` не предлагаются в hreflang. Для категорий RU/EN требуется заполнить не только название и описание, но и SEO title/description — одинаковое условие применяется к middleware и sitemap. Для legacy `/products/<slug>` alternates формируются по каноническому пути `/product/<slug>`.
- Исходник Sanity Studio в GitHub содержит поля переводов, но развёрнутая схема `florial-admin` их пока не показывает. Схема не развёртывалась и документы Sanity не менялись. Перед deployment нужно сверить schema source со всеми существующими полями, особенно тип `service.slug`.

## 2026-10-22 — Исправления SEO и структурированных данных

- В src/lib/seo.ts добавлены единое управление og:image / twitter:image, очистка устаревшей JSON-LD-разметки при SPA-переходах и возможность задавать язык HTML.
- Для главной и контактов добавлены локализованные title/description на BG/RU/EN и hreflang для поддерживаемых языковых URL.
- В index.html добавлены статические Open Graph/Twitter image метаданные и минимальная JSON-LD-разметка Organization без неподтверждённых адресов, телефонов или юридических реквизитов. Для изображения используется опубликованный логотип Florial в Sanity CDN.
- На карточках товаров добавлена JSON-LD-разметка Product с ценой в EUR, SKU при наличии, изображением и подтверждённым статусом наличия; добавлена BreadcrumbList. Статус «по заявке» не преобразуется в неподтверждённое обещание о сроке поставки.
- На страницах категорий добавлена BreadcrumbList. Для RU/EN товаров и категорий hreflang и индексация допускаются только при наличии фактических переводов; непереведённые варианты получают noindex.
- Для /cart, /search, неизвестных URL и несуществующих товаров/категорий/услуг добавлен noindex, nofollow. Неизвестные URL также получают HTTP 404 через Cloudflare middleware. Старый /products/... нормализуется в canonical /product/....
- Динамический sitemap теперь включает языковые URL главной, контактов, категорий и товаров только при наличии достаточного переведённого контента и SEO-полей.
- В functions/_middleware.ts добавлена серверная проверка URL товаров, категорий и услуг по публичным Sanity datasets. Неизвестные URL и несуществующие документы возвращают настоящий HTTP 404 с X-Robots-Tag noindex. Проверка preview deployment: существующий товар и услуга — HTTP 200, несуществующий товар и неизвестный URL — HTTP 404, JS-asset — HTTP 200. Эти проверки сделаны на preview deployment; после последующих коммитов нужна повторная production-проверка.
- Удалён public/_redirects: Cloudflare Pages сообщал об infinite-loop и игнорировал правило /* → /index.html 200. Проверка preview после этого предупреждения показала, что действующие SPA-маршруты продолжают открываться.
- В functions/_middleware.ts добавлен edge prerender начального HTML: для главной и контактов локализуются title, description, canonical, Open Graph/Twitter и hreflang; для товаров, категорий и услуг сервер подставляет SEO-заголовок, описание, canonical/hreflang, Open Graph, краткий содержательный блок в root и JSON-LD Product/BreadcrumbList. Это не полный React SSR: после загрузки клиентский React заменяет root, а серверный HTML служит контентным fallback для роботов и превью.
- Ограничение Sanity: deployed schema florial-admin не содержит полного блока translations в типах product/category/service. Исходник studio/schemaTypes/index.ts теперь содержит поля переводов и SEO для товаров/категорий; активная Studio не развёртывалась и данные не мигрировались. В исходнике slugField теперь использует Sanity slug для товаров/категорий/растений, а поле услуги оставлено строкой в соответствии с фактическим значением, которое вызвало ошибку в Studio. Deployed schema всё ещё ожидает slug object для услуги; требуется сверить остальные отличия схем и вручную развернуть совместимую схему.
- Preview deployment ed70a063 (commit b8fba125) завершился успешно. Firecrawl подтвердил локализованные server-head метаданные для RU product/homepage и EN contacts, а несуществующий товар вернул HTTP 404. Более поздние изменения canonical/Open Graph и sitemap ещё требуют проверки последнего deployment и основного домена.
## 2026-10-22 — Защита workflow Sanity от автоматического deployment

- Исправлены оба GitHub Actions workflow Studio: push в `main` запускает сборку/проверку, но не развёртывает Sanity schema или hosted Studio автоматически.
- Deployment существующей Studio и schema теперь требует ручного запуска workflow (`workflow_dispatch`). Это предотвращает повторное развёртывание при обычных изменениях SEO/контента.
- После изменения схемы проверено через Sanity API, что проект по-прежнему содержит те же три Studio приложения; новая Studio не создавалась.
- Текущая опубликованная схема `florial-admin` всё ещё не показывает новый блок `translations`; синхронизация схемы остаётся отдельной задачей и требует ручного review перед deployment.

- Для URL услуг добавлены self-canonical с сохранением `?lang=ru` и `?lang=en`; болгарские URL остаются без параметра языка.

- В `src/App.tsx` canonical и `og:url` сохраняют выбранный язык при SPA-навигации.
- Динамический `functions/sitemap.xml.ts` расширен: в карту добавляются URL русской и английской версии услуги только если в Sanity заполнены соответствующие локализованные SEO title и description.
- После публикации необходимо проверить sitemap и canonical/hreflang на production. Параметрические URL применены как совместимый текущей архитектуре вариант; отдельные языковые каталоги `/ru/` и `/en/` не создавались.

- Обновлены SEO-заголовки и meta descriptions всех 6 активных услуг в Sanity dataset `production`.
- Добавлены локализованные поля `translations.en.seo` и `translations.ru.seo`; текущий frontend использует локализованное поле SEO при выборе языка.
- Географические запросы распределены между страницами: Несебър/Nessebar/Несебр, Слънчев бряг/Sunny Beach/Солнечный Берег, Равда/Ravda/Равда, Свети Влас/Sveti Vlas/Святой Влас, Ахелой/Aheloy/Ахелой, Поморие/Pomorie/Поморие, Каблешково/Kableshkovo/Каблешково и Кошарица/Kosharitsa/Кошарица.

- Изменения Sanity опубликованы для всех 6 услуг. Проверка production через Firecrawl подтвердила корректные локализованные title на болгарском, русском и английском для проверенных URL.

## 2026-10-22 — Техническое SEO: robots.txt и динамический sitemap.xml

- Добавлен `public/robots.txt` с разрешением обхода публичных страниц (`User-agent: *`, `Allow: /`) и ссылкой на `https://florial-bg.com/sitemap.xml`.
- Добавлена Cloudflare Pages Function `functions/sitemap.xml.ts`, которая динамически получает активные услуги, товары и категории из публичных Sanity datasets `production` и `plants`.
- В карту включаются главная, контакты, страницы услуг, категории и карточки активных товаров; документы с `seo.noIndex = true` пропускаются там, где это поле предусмотрено.
- URL формируются на основном домене `https://florial-bg.com`; языковые query-параметры не дублируются в карте, поскольку canonical URL сайта использует основной путь.
- Для карты установлен короткий CDN-кэш (5 минут), чтобы новые публикации Sanity появлялись без ручного редактирования XML после истечения кэша.
- Публикация и production-проверка sitemap выполняются отдельно; наличие исходного файла само по себе не считается подтверждением доступности endpoint.

- В Supabase удалена политика публичного создания заказов; роли `anon` и `authenticated` больше не имеют прав чтения/записи таблицы `orders`.
- Для `products` и `product_categories` публичным ролям оставлено только чтение; фильтрация активных записей по-прежнему обеспечивается RLS.

- Добавлен файл миграции `supabase/migrations/20261022003000_harden_public_table_privileges.sql`, фиксирующий применённые изменения.
- Ограничение аудита: история Git до удаления `.env`, настройки Cloudflare/Sanity и полный end-to-end заказ отдельно не проверены.

## 2026-10-22 — Исправление вложенных URL и навигационных ссылок

- Удалён относительный `base: './'` из Vite; сборка использует стандартный корневой путь для ресурсов на основном домене.
- Добавлен общий обработчик внутренних ссылок: обычный клик сохраняет SPA-переход, а Ctrl/Cmd/Shift-клик и открытие ссылки через контекстное меню оставляются браузеру.
- Карточки услуг и категорий на главной, пункты меню услуг и категорий, хлебные крошки, карточки товаров в категориях и поиске, а также совместимые товары переведены на настоящие ссылки с `href`.
- Позднее `public/_redirects` удалён, поскольку Cloudflare Pages сообщал об ошибке infinite-loop для правила `/* → /index.html 200`. Историческая запись выше не отражает текущее состояние файла.
- В `functions/_middleware.ts` добавлена проверка существования товара/категории/услуги через публичный Sanity API; несуществующие документы и неизвестные URL возвращают HTTP 404 и `X-Robots-Tag: noindex, nofollow`. Служебные `/cart` и `/search` помечаются `noindex, nofollow`; для legacy `/products/<slug>` canonical нормализуется к `/product/<slug>`.
- Edge middleware формирует server-side title, description, canonical, hreflang, Open Graph/Twitter и JSON-LD для Organization, Product и BreadcrumbList. Для товаров RU/EN, где полный перевод не подтверждён, выставляется `noindex` и canonical на болгарский URL; такие языковые варианты не должны попадать в sitemap.
- Production-проверка 22.10.2026: карточка `f54228` — HTTP 200, Product и BreadcrumbList JSON-LD; растение `rakat-na-buda?lang=ru` без полного перевода — `noindex, nofollow` и canonical на базовый болгарский URL; несуществующий товар — HTTP 404; корзина/поиск — noindex. Последний тест Organization JSON-LD ожидает завершения нового deployment.
- Ограничение: это edge-подстановка начального HTML и метаданных, а не полный React SSR/SSG. Проверить все варианты языков и страницы после последнего deployment ещё требуется.
- Контекстное меню/долгое нажатие в реальном браузере пользователя требует финальной проверки на устройстве.
