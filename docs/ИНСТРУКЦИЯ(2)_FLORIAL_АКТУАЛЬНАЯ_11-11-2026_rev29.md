# Florial — дополнение к технической инструкции MD2 rev29
Дата: 11.11.2026

> Этот документ является дополнением к Library-инструкции ИНСТРУКЦИЯ(2)_FLORIAL_АКТУАЛЬНАЯ_09-11-2026_rev28.md. Он не заменяет архитектурные правила и исторические разделы rev28.

## Политика конфиденциальности

- Публичный URL: /privacy-policy; языки BG (основной), RU и EN через ?lang=ru / ?lang=en.
- Страница рендерится отдельной веткой в src/main.tsx, использует LanguageProvider, существующий applyPageSeo и общий Footer.
- Ссылка добавлена после Copyright в src/components/Footer.tsx; три локализованных URL добавлены в functions/sitemap.xml.ts.
- Runtime обработчики, Sanity, D1 schema/data, Manager, checkout, Header и главное меню не менялись.
- Фактические поставщики в политике: Cloudflare (Pages/Functions/D1 и защита), Sanity (контент), Resend (email), курьерские компании по фактической доставке. Supabase не указывать как действующий runtime.
- Статистика сайта: page_view/call/chat event, язык, path и timestamp. Защита публичных форм использует Cloudflare IP и дневной SHA-256 hash для rate limit; rate-limit записи имеют срок до 48 часов. Не утверждать, что инфраструктура вообще не обрабатывает IP.
- Корзина и язык используют localStorage. Встроенные YouTube-видео загружаются через youtube-nocookie iframe; не утверждать, что сторонняя обработка происходит только после нажатия Play.
- Service leads: предусмотрен review horizon до 365 дней, но автоматическое удаление в текущем коде не реализовано. Это открытый вопрос; не обещать автоматическое удаление. Production purge/анонимизацию не выполнять без отдельного подтверждения.
- Юридический текст требует проверки болгарским юристом и сверки с договорами/настройками каждого обработчика, сроками хранения бухгалтерских документов, transfer safeguards и реквизитами из Търговския регистър.
- Не менять Footer/Header/глобальную оболочку сверх явно согласованной ссылки. Не создавать новые CMP/cookie banner или tracking consent flow без отдельного аудита и согласования.

- Файлы: src/pages/PrivacyPolicyPage.tsx, src/main.tsx, src/components/Footer.tsx, functions/sitemap.xml.ts, docs/TECHNICAL_PASSPORT.md, CHANGELOG.md, docs/ROADMAP_SERVICES_AND_LEADS.md.
- PR, CI, merge и Production deployment должны быть подтверждены отдельно. До успешного deployment не утверждать, что страница опубликована.
## Дополнение rev29 — обязательный middleware route для статических legal pages

- Любая новая статическая React page, добавленная отдельным путём через src/main.tsx, должна быть разрешена в functions/_middleware.ts до общего notFoundResponse.
- Для публичной индексируемой legal page middleware должен возвращать SSR fallback с локализованными H1/intro, title, description, self-canonical, hreflang и index/follow. Одного client-side React route недостаточно.
- После deploy обязательно проверять прямой HTTP URL без JavaScript и варианты ?lang=ru / ?lang=en. Проверять status code, robots, canonical, title и H1. Sitemap 200 сам по себе не подтверждает, что route доступен.
- Для privacy-policy этот route добавлен в отдельной правке после выявленного 404; CI и Production результат должны быть внесены после проверки.
