# Florial Manager — первичное включение на Cloudflare D1

## Текущая архитектура

- Операционная база: Cloudflare D1, binding DB, база florial-db, jurisdiction eu.
- Каталог растений и фотографии: Sanity project bxvcy0qs, dataset plants.
- Письма: Resend.
- Авторизация: email + постоянный пароль; пароли хранятся только как PBKDF2-SHA-256 хеш с индивидуальной солью. В браузере сессия — HttpOnly Secure cookie, токен в localStorage не сохраняется.
- Роли: seller, manager, owner.
- Первичный owner создаётся одноразовым bootstrap endpoint только при отсутствии owner-профиля. Для него требуется серверный secret MANAGER_BOOTSTRAP_SECRET; секрет нельзя помещать в frontend или Git.

## Настройка после merge

1. Создать D1 database florial-db с jurisdiction eu.
2. Привязать её к Pages project florial как production binding DB.
3. Применить SQL миграции из functions/migrations/ строго по порядку.
4. Установить production secret MANAGER_BOOTSTRAP_SECRET и выполнить однократное создание owner через POST /api/manager/auth/bootstrap. После появления owner endpoint автоматически закрывается.
5. Убедиться, что owner может войти на /manager, затем создать сотрудников из раздела «Сотрудники», задавая email, имя, роль и постоянный пароль.
6. Проверить создание заявки, загрузку фото в Sanity Assets, AI-обработку, review, публикацию, заказы и аналитику.
7. Старый Supabase оставить неизменённым на согласованный rollback-период. Не выполнять dual-write и не удалять старые данные/проект без отдельного подтверждения.

## Фотографии

- Продавец загружает фото через защищённую Pages Function.
- Разрешены JPEG, PNG и WebP, до 10 MB на файл.
- Проверяются MIME type и сигнатура содержимого.
- Файл сразу записывается в публичный Sanity dataset plants. Прямая CDN-ссылка может быть доступна до публикации карточки — это согласованное владельцем поведение.
- D1 хранит URL и Sanity asset ID в JSON заявки; бинарные файлы в D1 не сохраняются.

## Авторизация и защита

- Сотрудника создаёт только owner.
- Пароль не отправляется по email и не хранится в открытом виде.
- Смена пароля отзывает все текущие сессии сотрудника.
- Деактивация сотрудника немедленно отзывает его сессии.
- Вход ограничен rate limit: 8 неудачных попыток на сочетание email/IP за 15 минут, затем временная блокировка.
- Сессия обновляется скользящим сроком до 30 дней; cookie HttpOnly, Secure, SameSite=Strict.
- Owner bootstrap должен быть доступен только один раз.

## Важно

Не запускать SQL с DROP, не чистить таблицы и не удалять Supabase без отдельного подтверждения владельца. Исторические Supabase migrations остаются в репозитории как архив миграций исходной системы; они не применяются к D1.
