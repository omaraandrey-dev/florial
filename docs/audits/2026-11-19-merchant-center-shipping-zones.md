# Florial — Merchant Center: локальные тарифы доставки оборудования

Дата проверки: 2026-11-19  
Базовый GitHub `main`: `27db23ee22abd214047b3d41d7f430ab30b10d1b`  
Production: https://florial-bg.com

## Вывод

Опубликованные условия Florial позволяют сформировать локальную карту доставки оборудования для 30 населённых пунктов в 6 ценовых группах. Для Google Merchant Center нельзя переносить эти тарифы на всю Болгарию и нельзя применять их к живым растениям.

Google Merchant Center поддерживает региональную доставку через атрибут `shipping` с одним из географических податрибутов: `location_id` (критерий Google Ads Geo Target) либо `location_group_name` (группа местоположений, созданная в Merchant Center → Regions). Оба варианта официально описаны Google. На первом проходе проверяется предпочтительный для владельца `location_id`; если для отдельных малых населённых пунктов Google не предоставляет точный активный критерий, не подставлять ID соседнего города или всей области — рассмотреть Merchant Center location group как альтернативу и отдельно подтвердить её пригодность.

## Источник тарифов Florial

Публичная страница: https://florial-bg.com/services/dostavka-poliv

Тарифы относятся только к доставке заказанного оборудования для систем полива. Бесплатная инженерная консультация на объекте — отдельная часть сервиса и не является стоимостью доставки. На странице не опубликован срок доставки; поэтому `min_handling_time`, `max_handling_time`, `min_transit_time` и `max_transit_time` не заполнять до подтверждения фактических сроков.

## Проверка Google географии

- Google Ads Geo Targets предоставляет официальный CSV-справочник с Criteria ID, Name, Canonical Name, Parent ID, Country Code, Target Type и Status; актуальный файл на момент проверки датирован 2026-10-06: https://developers.google.com/google-ads/api/data/geotargets
- Google Ads API также поддерживает поиск GeoTargetConstant по названиям через `SuggestGeoTargetConstants`.
- Сам файл CSV опубликован как ZIP: https://developers.google.com/static/google-ads/api/data/geo/geotargets-2026-10-06.csv.zip. Доступные инструменты в текущей сессии не смогли скачать/распаковать ZIP; поэтому точные Criteria ID для 30 населённых пунктов пока **НЕ ПОДТВЕРЖДЕНЫ**.
- Нельзя выводить Criteria ID из названия, геокодировать город в произвольный Google Maps ID или использовать ID родительского муниципалитета без проверки границ охвата.
- Если для небольшого населённого пункта нет отдельного активного Geo Target, проверить вариант с `location_group_name` и Merchant Center Regions. Google указывает, что имя группы должно соответствовать группе, предварительно созданной в настройках Regions.

## Рекомендуемая модель конфигурации

1. Создать Merchant Center аккаунт и подтвердить/заявить домен `florial-bg.com`.
2. Получить точные активные Geo Target Criteria ID для всех 30 населённых пунктов из официального справочника/API. Для каждого ID проверить Country Code = BG, Status = Active и однозначное соответствие нужному населённому пункту.
3. Создать шесть тарифных правил/региональных групп оборудования по опубликованным EUR-ценам. Предпочесть account-level shipping settings, как рекомендует Google; не дублировать те же тарифы product-level overrides без необходимости.
4. Если Google не предоставляет точный Geo Target для некоторых поселений, проверить возможность включить их в отдельную Merchant Center Region group. Не расширять покрытие на весь муниципалитет/область без подтверждения, что реальная зона доставки совпадает.
5. Разделить оборудование и живые растения через разные product groups / shipping labels. Не применять Z0–Z25 к растениям.
6. Для растений оставить индивидуальное согласование доставки. Не задавать фиксированный тариф, срок или общеболгарское покрытие, пока бизнес не утвердит стандартную политику, совместимую с реальным процессом.
7. Не задавать сроки обработки/перевозки: опубликованная страница не содержит подтверждённых сроков.
8. Проверить итоговую конфигурацию на тестовых товарах в Merchant Center и сверить расчёт с опубликованной страницей Florial.

## Технические ограничения

- Не добавлять общеболгарский `ShippingService` / `OfferShippingDetails` в JSON-LD: стандартная Google Search schema.org-разметка не позволяет достоверно ограничить зоны доставки по всем этим болгарским населённым пунктам.
- Существующая Organization `MerchantReturnPolicy.merchantReturnLink` на `/terms` остаётся без изменений. Не добавлять универсальные return days, return fees или методы возврата, которых политика не устанавливает для всех случаев.
- Отсутствие фиксированной доставки для растений не является основанием приписывать им тарифы оборудования.
- На этом этапе не реализовывать автоматический feed endpoint: сначала завершить этапы создания Merchant Center, выбора регионального механизма и согласования product eligibility. Динамический feed остаётся отдельным этапом дорожной карты.
