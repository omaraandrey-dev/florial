# Manager — минимальное добавление растения

Дата: 2026-11-21  
Ветка реализации: `fix/manager-plant-minimal-intake`  
Основа: `main` на commit `97c9d1cd1031ad2d2881dfeecb03ed73ded1c388`.

## Цель

Разрешить сотруднику сохранить новую карточку растения без обязательного Google-поиска, категории и фотографии. Google Text также должен применяться без фотографии. Продавец может внести минимальный коммерческий набор и дополнить контент позднее.

## Минимальные данные для сохранения

- Название растения.
- Не менее одного варианта продажи.
- Цена варианта EUR > 0.
- Количество — целое число >= 0.
- Для варианта достаточно либо вручную введённого названия модели/размера, либо одновременно высоты и объёма контейнера.

Категория, основная фотография, научное название, описания, переводы, SEO и ботанические характеристики не блокируют первоначальное сохранение.

## Безопасность и видимость

- Google proof остаётся подписанным текущей Manager session. Для Text proof фиксируется режим `text` без привязки к фотографии, даже если продавец уже выбрал файл, который не отправлялся в Google. Для Photo proof и Text proof с выбранной фотографией сохраняется совместимая привязка к Sanity image asset, включая существующий сценарий добавления варианта.
- Сервер принимает создание без Google proof только при успешной проверке минимальных коммерческих полей.
- Серверная проверка повторяет требования по цене, количеству и названию/размеру варианта при создании. Редактирование существующих растений сохраняет прежние требования к категории, фотографии и размеру; для статусов вне `inStock` количество по-прежнему может оставаться пустым.
- Если при создании отсутствует категория или основная фотография, Sanity документ сохраняется с `isActive=false`. Он виден в Manager, но не публикуется в публичном магазине до последующего заполнения категории и фотографии и ручной активации.
- При количестве 0 UI автоматически переключает статус варианта с `inStock` на `outOfStock`; серверная проверка существующего правила `inStock` остаётся действующей.

## Ограничения проверки

Это изменение кода Manager и Pages Functions. Sanity schema, опубликованные документы, D1 schema/data, Cloudflare settings/secrets, Resend и Production не изменяются. Не создавать тестовые растения в Production для QA. CI/Preview/Production проверки фиксируются отдельно после получения результатов точного PR head.
