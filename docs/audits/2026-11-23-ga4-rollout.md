## Code implementation in this branch

- GA4 tag `G-2H9DQTLVZY` is dynamically loaded only after the existing analytics consent is accepted.
- No Google tag is loaded for unknown/rejected consent.
- Consent acceptance grants `analytics_storage` only; advertising consent signals remain denied.
- Consent withdrawal updates GA4 consent to denied; re-acceptance explicitly restores analytics consent. PostHog remains gated by the same existing choice.
- Page locations are built from origin + pathname, not the query string.
- Explicit events implemented: `page_view`, `view_item`, `view_cart`, `add_to_cart`, `remove_from_cart`, `begin_checkout`, `purchase`.
- The App replays the current page and content-view events after consent is granted without duplicating the D1 baseline page-view write.
- Re-accepting analytics after withdrawal restores GA4 consent; consent is queued before the Google tag configuration.
- The order API adds a non-PII `analyticsPurchase` response only after the order is saved in D1. The amount and product line items are calculated from server-validated catalogue prices. The browser sends GA4 `purchase` with the unique order number as `transaction_id`, EUR value, optional shipping and item lines.
- Customer name, phone, email, address, comment, payment details and irrigation project data are not included in the GA4 payload.
- D1 baseline tracking and existing PostHog event transport are preserved.
