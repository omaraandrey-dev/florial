## Дополнение rev57 — изолированный тест Gemini для базы растений

### Цель
- Проверить качество Gemini 3.8 Flash на тех же фотографиях и исходных данных, которые использует текущий AI Manager.
- Не заменять Workers AI до сравнения минимум 10–15 растений.
- Не записывать тестовый результат в Sanity и не изменять текущую карточку.

### Реализация
- Новый серверный endpoint: POST /api/manager/plants/gemini-test.
- Модель: стабильная gemini-3.8-flash через Gemini Developer API.
- Доступ: только авторизованный owner; Manager/Seller получают HTTP 403.
- API key: Cloudflare Pages Production Secret GEMINI_API_KEY. Никогда не хранить в GitHub, клиентском коде, логах или Sanity.
- Запрос содержит только выбранную основную фотографию растения, поля формы и allowlist категорий Sanity. Фото принимается только с cdn.sanity.io/images/bxvcy0qs/plants/, JPEG/PNG/WebP, до 10 MB.
- Модель возвращает структурированный JSON: визуальное имя и confidence, до трёх латинских гипотез, productType, categoryId, BG/RU/EN descriptions, SEO, image ALT, care fields и careGuide.
- Категория принимается только при совпадении с ID из переданного списка. Латинские кандидаты не являются подтверждённым scientificName; GBIF в тесте не вызывается.
- Один вызов без автоматического повтора; timeout модели 120 секунд. Ошибки квоты показываются отдельно.
- Результат отображается отдельно от существующей AI-формы; он не заполняет поля, не создаёт AI proof, не сохраняет, не публикует и не меняет цену, размер, SKU или наличие.

### Область
- Разрешены изменения только тестового endpoint/helper, тестового блока Owner в src/manager/PlantCatalogManager.tsx, ManagerEnv, unit tests и технической документации.
- Запрещено менять существующий ai-enrich.ts, Workers AI, Sanity schema/data/assets, D1 schema/data, другие AI функции, checkout/orders, Header/menu/Footer и глобальную структуру сайта без отдельного согласования.

### Настройка и приёмка
1. В Cloudflare Pages → Settings → Variables and Secrets → Production добавить GEMINI_API_KEY как Secret. Значение не отправлять в чат и не помещать в GitHub.
2. Выполнить CI и проверить Production deployment после merge.
3. Проверить Owner доступ и отказ Manager/Seller.
4. Прогнать 10–15 разных фотографий; сопоставить с Workers AI по правильности названия, уверенности, описаниям, BG/RU/EN, SEO и осторожности ботанических утверждений.
5. Не переключать основную кнопку на Gemini до отдельного решения Owner.
6. В техническом паспорте и CHANGELOG фиксировать фактические CI/deploy/live results. Не заявлять об успешном подключении, пока secret не добавлен и live test не выполнен.
