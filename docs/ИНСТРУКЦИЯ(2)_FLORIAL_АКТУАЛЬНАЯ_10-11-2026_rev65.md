## Дополнение rev65 — обнаружение существующих растений и append нового варианта

### Решение владельца
- После идентификации Google Manager проверяет опубликованный каталог Sanity plants на существующую карточку по основному имени, переводам BG/RU/EN и ботаническим кандидатам.
- Если найдены совпадения, возле предложенного имени показывается кликабельная красная точка. По нажатию сотрудник видит список карточек с фотографией, названием, латинским названием, категорией и текущими вариантами.
- При выборе существующей карточки сотрудник добавляет только свободный текст размера и цену EUR. Повторяющиеся размеры/высоты разрешены. Количество стволов не является отдельным полем и при необходимости записывается в текст размера.
- Новая фотография добавляется в общую галерею карточки растения, не связывается с отдельным вариантом. Главная фотография и существующие снимки не заменяются.
- Если сотрудник не выбирает существующую карточку, он может закрыть список и продолжить создание новой карточки.

### Runtime и безопасность
- Read-only duplicate endpoint: GET /api/manager/plants/duplicates; exact match без учёта регистра по name, translations.bg.name, translations.ru.name, translations.en.name, scientificName и legacy plantDetails.scientificName; drafts исключены; максимум 12 результатов.
- Append endpoint: POST /api/manager/plants/:id/add-variant.
- Новый вариант использует существующий plantSaleVariant: _key, name, priceEUR, stockStatus=onRequest, stockQuantity=null. Отдельные поля stems, height variant photo или новые Sanity schema fields не создаются.
- Существующие варианты сохраняются; повторяющиеся размеры не блокируются; максимум 30 вариантов.
- Проверенная Google фотография добавляется в gallery, только если asset ещё не присутствует в mainImage/gallery и не превышен лимит 10 фотографий всего с учётом mainImage. При заполненной галерее размер/цена могут быть добавлены без фото.
- Сервер проверяет активную Manager session, роль, same-origin, HMAC aiProof и совпадение с текущим image asset, существование Sanity asset, Sanity _rev, idempotency и существующий D1 manager_product_audit.
- При конфликте ревизии изменения не перезаписываются. Повторная отправка использует тот же idempotency key и variant key.
- Никаких Sanity schema/data migrations и D1 schema/data migrations для функции не требуется.

### Текущее поведение
- Основная модель: `gemini-3.5-flash-lite`.
- Endpoint: `POST /api/manager/plants/gemini-test`; он используется как основной endpoint заполнения растений.

- При подтверждении эти значения берутся из открытой карточки и передаются в существующий API сохранения без изменения.
- AI обновляет только поля контента: name, productType, category, descriptions BG/RU/EN, SEO BG/RU/EN, ALT основной фотографии в Photo режиме; Owner дополнительно может обновить plantCare и careGuide.
- Серверный `aiProof` подписывается текущей Manager session и связывается с asset ID основной фотографии. Create/update API продолжает проверять proof, роль, same-origin, idempotency key, expected Sanity revision и audit log.
- Если не заполнены обязательные поля нового товара (категория, размер, цена/вариант, фото и т.д.) или имя не подтверждено, Sanity mutation не выполняется. Manager показывает ошибку и сохраняет введённые данные в форме для исправления.

## Дополнение rev60 — два потоковых режима Gemini для Owner

### Назначение
- В Owner панели Manager растений должны быть две отдельные тестовые кнопки:
  - **Gemini Photo** — передаёт основную фотографию растения из Sanity plants CDN и текущие поля продавца.
  - **Gemini Text** — передаёт только введённое название/текст растения, например «лавровишня». Изображение не загружается и не включается в запрос.
- Оба режима используют модель `gemini-3.8-flash`, но отправляют разные prompt и input payload, чтобы сравнить качество и время обработки изображения и текста.
- Для Text название пользователя — предмет ботанического анализа; модель должна вернуть наиболее вероятную идентификацию, до трёх кандидатов с объяснением, категорию только из фактического списка Manager, тип растения, описание BG/RU/EN, SEO и характеристики ухода.
- Для Text не генерировать визуальное описание и ALT: фотографии нет. Эти поля возвращаются пустыми.
- Не утверждать, что модель выполнила внешний веб-поиск или проверку GBIF, если отдельная интеграция реально не запускалась.

### Потоковый режим и Owner диагностика

- Общий timeout Google generation — 300 секунд; browser watchdog — 310 секунд. Ошибка загрузки изображения не должна классифицироваться как timeout генерации.
- Не возвращать и не логировать API key, raw provider response body, headers, image bytes или другие секреты.

### Ограничения безопасности и scope
- Обе кнопки доступны только роли Owner с действующей Manager session и same-origin проверкой.
- Тесты не меняют форму, не создают AI proof, не сохраняют в Sanity/D1 и не публикуют товары.
- Существующая Workers AI кнопка «Попълни с ИИ» и основной AI workflow не изменяются.
- Не менять схемы/документы Sanity, D1, checkout/orders, Cloudflare secrets/settings, Header/menu/Footer или глобальную структуру.
