# Florial Manager — мобильный сценарий приёмки растений

Документ относится к PR #44. Проверка выполняется после merge и production deployment либо на безопасном Preview, если для него отдельно подтверждены нужные Supabase bindings. Не создавать тестовые заявки в production без согласования.

## Проверка сотрудника на телефоне

1. Войти в `/manager` под ролью `seller`.
2. Нажать «Ново растение».
3. В поле категории открыть выпадающий список и выбрать «Маслини». Категории загружаются из Sanity dataset `plants`.
4. Заполнить тестовые поля растения и варианта продажи.
5. Выбрать две фотографии или сделать их через системный выбор камеры/галереи.
6. Убедиться, что обе миниатюры видны до сохранения; удалить один снимок и добавить его повторно.
7. Нажать «Запази черновата». Во время загрузки должен отображаться прогресс; после завершения должно быть явно указано количество сохранённых фотографий.
8. Убедиться, что сохранённые фотографии видны в карточке заявки. Повторно открыть черновик и проверить, что выбранная категория и фотографии сохранились.
9. Отправить заявку на проверку. Кнопка отправки должна быть недоступна, пока есть ожидающие загрузки файлов.

## Проверка владельца и менеджера

1. Войти под ролью `owner` и открыть ту же заявку.
2. Проверить название, латинское имя, категорию, SKU, описание, вариант, высоту, объём контейнера, цену, количество и наличие.
3. Открыть каждую фотографию из карточки заявки и убедиться, что доступны оба снимка.
4. Проверить возврат на исправление с комментарием.
5. На отдельной тестовой заявке проверить отклонение с причиной.
6. На отдельной тестовой заявке проверить одобрение с подтверждением.
7. Убедиться, что одобрение меняет только статус заявки. Финальная проверка и публикация выполняются отдельной owner-only формой, описанной ниже.

## Ожидаемый результат

- Категория записывается как Sanity document ID в `payload.categoryId` и название в `payload.categoryName`.
- Каждый успешно загруженный файл сохраняет свой Storage path в `payload.images`.
- Фотографии находятся в закрытом bucket `florial-manager-intake`; владелец видит их через временные подписанные URL.
- Неудача последующей фотографии не должна терять ссылки на ранее загруженные изображения.
- Действия одобрения, возврата и отклонения отражаются в истории заявки.

## Ограничения

- Максимум 8 фотографий на заявку, до 10 MB каждая.
- Фактическая работа камеры и обработка HEIC зависят от браузера и Android/iOS file picker; это необходимо проверить на используемом телефоне.
- До ручной проверки на телефоне не считать мобильную загрузку подтверждённой.

## Финальная карточка и публикация в Sanity (PR #45)

1. Под owner открыть одобренную заявку с двумя фотографиями. Владелец должен увидеть отдельную форму финальной карточки; сотрудник seller эту форму не видит.
2. Проверить BG название, ботаническое имя, slug, тип растения, категорию из Sanity, SKU, описания, вариант продажи, цену EUR с ДДС, наличие и количество.
3. Проверить обе фотографии, выбрать главную и проверить alt-тексты. При недоступной хотя бы одной фотографии публикация должна быть заблокирована.
4. При необходимости заполнить EN/RU переводы и SEO. Сохранить финальную версию, обновить страницу и убедиться, что данные восстановились из `payload.publication`, а исходный payload сотрудника остался неизменным.
5. Убедиться, что кнопка публикации доступна только после сохранения текущей версии и требует подтверждения.
6. После настройки Cloudflare Production Secret `SANITY_API_TOKEN` использовать только отдельную тестовую заявку, согласованную владельцем. Публикация должна перенести фотографии из private Supabase Storage в Sanity Assets, создать `product` в dataset `plants` и проверить документ чтением.
7. Проверить `published`, `published_at`, Sanity document ID, категорию, `saleVariants`, `mainImage`, `gallery`, `vatIncluded=true` и `isActive=true`.
8. Проверить повторный вызов и частичный сбой: повторная попытка должна использовать сохранённый document ID/asset IDs и не создавать дубликат. При ошибке статус `publish_failed`, исходные фото остаются в private Storage.

### Отдельная настройка Cloudflare

- На момент проверки в Production отсутствует `SANITY_API_TOKEN`; публичные `VITE_SANITY_*` не являются write credentials.
- Подключение Sanity management connector для административной работы не заменяет серверный токен, используемый сайтом.
- Токен должен быть добавлен владельцем непосредственно в Cloudflare Pages Production Secrets; не присылать его в чат и не добавлять в GitHub.
- До добавления токена публикация должна завершаться сообщением о ненастроенном сервере и не переводить заявку из `approved`.
