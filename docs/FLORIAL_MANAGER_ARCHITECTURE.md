# Florial Manager — архитектура

## 2026-11-02 — переход на Cloudflare D1

- Операционные данные (заказы, события сайта, сотрудники, сессии, заявки и аудит) хранятся в Cloudflare D1.
- Sanity остаётся единственным источником каталога и фотографий. Фото продавцов сразу загружаются в публичный dataset plants; разрешены JPEG, PNG и WebP до 10 MB.
- Авторизация сотрудников — email + постоянный пароль. Пароли хранятся PBKDF2-SHA-256 с индивидуальной солью; сессии хранятся в D1, браузер получает HttpOnly Secure SameSite=Strict cookie.
- Роли: seller, manager, owner. Проверка прав выполняется сервером на каждом защищённом endpoint.
- Cloudflare Pages Functions используют D1 binding DB. Supabase больше не является частью целевой архитектуры.
- Существующий Cloudflare Workflow для ботанической проверки и Workers AI сохраняются; workflow process авторизуется отдельным случайным job token, сверяемым с заявкой в D1.
- Resend остаётся провайдером почты.
- Тестовые записи Supabase не мигрируются. Старый Supabase оставляется только на период rollback и не должен получать новые записи.
- Header, menu, Footer, публичная навигация и Sanity schemas не меняются.

## Принципы

1. Sanity — единственный источник истины для товаров, растений, категорий и опубликованных карточек.
2. D1 — единственный источник истины для заказов, сотрудников, заявок, статусов, истории и аналитики.
3. Бинарные фотографии не сохраняются в D1; в заявке хранятся Sanity asset ID и URL.
4. Клиентский код не имеет прямого доступа к D1. Все операции идут через Pages Functions.
5. Пароли, токены сессий и API secrets не сохраняются в открытом виде и не передаются в клиентский JavaScript.
6. Удаление старых данных и отключение Supabase — отдельное согласование после rollback-периода.

## Рабочий процесс растений

1. Seller создаёт черновик в D1 и загружает фотографии в Sanity Assets.
2. Seller отправляет заявку на проверку; D1 фиксирует статус и событие аудита.
3. Manager может вернуть заявку на исправление, но не может одобрить или публиковать её.
4. Owner проверяет заявку, AI-черновик, ботаническое исследование и финальную карточку.
5. Owner одобряет заявку и отдельно публикует растение в Sanity.
6. Публикация использует уже загруженные Sanity Assets и не дублирует изображения.
